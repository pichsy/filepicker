# 微信式图片编辑器：真实 UI 状态机 + 算法方案（自己实现，不反编译）

> 依据：需求方提供的微信 8.0.74 实机截图 5 张（涂鸦/文字/裁剪初始/裁剪拖拽/马赛克）。
> 本文只讲**从截图反推出来的真实交互**与**算法**，不涉及任何反编译产物。

## 零、关于"反编译微信"

不做。原因：微信是乐固加固 + R8 混淆，dex 被抽取、核心在 native，反编译只能看到壳；
且用户协议禁止逆向工程。**我们复刻的是效果与交互，不是它的代码。**

## 一、真实 UI 状态机（来自 5 张截图）

### 1.1 常态（编辑中）

```
┌───────────────────────────────────────────┐
│ 取消                          ↶ 撤销   ↷ 重做 │  顶部条：全局撤销/重做
│                                           │
│                 图片画布                    │  图片 fit 屏幕，黑底
│                                           │
│ ┌────── 二级面板（随当前工具变化）────────┐   │
│ │ 涂鸦：◇橡皮 │ ● ● ● ● ● ● ● ●  (8 色)  │   │
│ │ 马赛克：◇橡皮 │ ▦像素  ◉模糊            │   │
│ │ 文字：…（文字样式）                      │   │
│ │ 表情：…（贴纸面板）                      │   │
│ └───────────────────────────────────────┘   │
│ ✏️涂鸦  😊表情  T文字  ⧉裁剪  ▦马赛克   [完成] │  工具栏 + 绿色主按钮
└───────────────────────────────────────────┘
```

* **4 个工具**：画笔（涂鸦） / 文字 / 裁剪 / 马赛克 —— **表情/贴纸不做**（我方无表情包资源，需求方已确认删除）；
* 选中哪个工具，它上面出现对应的**二级面板**，工具图标变绿；
* **全部用图标、不带文字**；底部工具条背景是**从下往上由半透明黑到透明**的渐变（不拦截触摸），
  工具区按导航栏高度让位；画笔的 8 个颜色点是 22dp 小圆点，一屏能全部放下；
* 「完成」始终在右下角绿色按钮，点它=应用全部编辑并生成新图；
* 顶部「取消 / 撤销 / 重做」在非裁剪态一直存在。

### 1.2 裁剪态（独立子状态）

```
┌───────────────────────────────────────────┐
│                                           │
│        ┌─────────────────┐  ← 裁剪框       │
│        │  ┊   ┊   ┊      │  细白线 + 三分构图线
│        │  ┊   ┊   ┊      │  + 四角 L 型括号
│        │  ┊   ┊   ┊      │  + 四边中点把手（8 个把手，可自由改大小）
│        └─────────────────┘                 │
│                                           │
│  ↰ 旋转                        还 原        │  二级条：旋转90° / 重置裁剪框
│                                           │
│  ✕                               ✓        │  底行：取消 / 确认（替换顶部条）
└───────────────────────────────────────────┘
```

**关键事实（和常见裁剪库不一样）**：

1. **没有比例预设**（没有 1:1 / 4:3 / 16:9 列表）——只有**自由裁剪**；
2. 初始框 = **整张图片的边界**；框内显示三分构图线；
3. 框有 **8 个把手**：4 个角 + 4 条边中点，可任意改大小和移动；
4. **框外图片仍然可见**（没有整屏压黑，最多轻微压暗），方便构图；
5. 底部：`↰ 旋转`（每次 90°）+ `还原`（把框重置回初始，没有改动时置灰）；
6. 确认/取消是底部的 `✕` / `✓`，此时**顶部条隐藏**；
7. 确认后回到常态，裁剪作为一次"操作"进入撤销栈。

### 1.3 各工具的真实二级面板

| 工具 | 二级面板内容（截图可见） |
|---|---|
| **涂鸦** | 左侧 `◇` 橡皮 + 8 个颜色圆点（白/黑/红/橙/黄/浅绿/绿/蓝），笔迹为实心线 |
| **马赛克** | 左侧 `◇` 橡皮 + 2 种笔刷：`▦像素马赛克`、`◉模糊`（截图里是柔和涂抹效果） |
| **文字** | 输入后在图片上生成文字（白色 + 深色描边/阴影），可拖动；裁剪态下文字仍显示 |
| ~~表情/贴纸~~ | **不做**（无表情包资源，已从需求中删除） |
| **裁剪** | 见 1.2 |

### 1.4 从截图能确认的架构结论（重要）

* **文字层在裁剪态仍然显示**（截图 4）→ 编辑器是**分层非破坏模型**：
  文字/涂鸦/马赛克/贴纸都是独立图层，裁剪只是对所有图层统一作用的一次变换；
* 马赛克有**两种笔刷**（像素块 / 模糊），不是单一算法；
* 涂鸦和**马赛克都有橡皮** → 需要"蒙版可擦除"的图层模型；
* 撤销/重做是**全局操作栈**（不限当前工具），裁剪、涂鸦、文字、马赛克都能撤销。

## 二、数据模型：非破坏 + 会话级覆盖（核心）

**这条是整个功能能安全落地的地基：编辑结果不改变"选中项的身份"，也不碰相册原图。**

```
选中项（身份不变）          编辑覆盖（会话级、临时）
┌──────────────────┐      ┌─────────────────────────────┐
│ MediaEntity(原图) │  →   │ EditSession                  │
│ path = 相册原图    │      │  ops: 裁剪/涂鸦/文字/马赛克…   │
│ 选中顺序、计数、规则 │      │  previewFile: 屏幕级预览临时文件 │
│ 全部按它算         │      │  editedFile : 原图级成品临时文件 │
└──────────────────┘      └─────────────────────────────┘
```

* 已选列表里**始终是原来的那张（原图实体）**：选中顺序、数量限制、互斥/分类型规则、
  去重、`indexOfSelected` 全部不受编辑影响 —— 这也是微信"编辑完选中态还是原图"的原因；
* 编辑结果单独挂在会话里：`Map<原图 path, EditSession>`；
* **相册原图绝不修改**：不写 MediaStore、不覆盖原文件；
  编辑产物只落在 `cacheDir/filepicker/edit/`；
* 任何展示位置都走同一个查找：`显示 URI = editSession?.previewFile ?: 原图`，
  所以网格缩略图、预览大图、底部缩略图条三处会**自动一致**；
* 即「本次选择中列表展示的数据已被编辑后图替换」，但选中身份仍是原图；
* 取消编辑 / 取消选择 → 删掉对应会话与临时文件，界面回到原图；
* 完成 → 回调里给"原图实体 + 编辑产物路径"，原图信息（path/originPath）仍可追溯。

### 2.1 会话数据结构

```
EditSession(
  originalPath: String,        // 原图身份（MediaEntity.path，判断等价的 key）
  ops: List<EditOp>,           // 非破坏操作栈（撤销/重做 + 再次进入编辑时续编）
  previewFile: File?,          // 屏幕级预览（编辑确认后立即产出，界面用）
  editedFile: File?,           // 原图级成品（后台异步产出，最终发送用）
  revision: Int,               // 每次变更 +1，界面按它做失效刷新
  isDirty: Boolean
)
```

### 2.2 产出时机（已定稿：完成即生成，不可撤销）

需求方确认的语义：

* **点「完成」= 立刻生成一张新图**，之后**不能撤回到原图**，再次进入编辑从**编辑后的图**开始；
* 编辑产物写到应用缓存目录：**默认 `Android/data/<包名>/cache/filepicker/`**，
  可由 `FilePicker.Builder.setEditCacheDir(path)` 换成宿主自己的目录；
* 缓存文件的生命周期由宿主掌握：宿主另存到自己的位置后，
  可调用 `FilePicker.clearEditCache(context)` 清理（`editCacheSize` 查占用、`editCacheDir` 拿目录）；
* 选择器启动时只做兜底清理（删超过 24h 的残留），**不会在返回结果后删除**；

| 时机 | 行为 |
|---|---|
| 点「完成」 | 导出新图到缓存目录（受 `setAvatarCropOutputMaxSize` 限制），作为新的展示内容 |
| 点「取消」 | 不产生文件，回到原图 |
| 再次编辑 | 以**编辑后的图**为输入（不是原图） |
| 返回宿主 | `entity.path` 仍是原图，`entity.editedPath` 指向编辑产物 |

### 2.3 回调兼容（不破坏现有 API）

```kotlin
// MediaEntity 新增只读字段，path 仍是原图
val editedPath: String?   // 非空 = 这张被编辑过，宿主上传/发送用这个
val isEdited: Boolean

// 宿主用法
val uploadPath = entity.editedPath ?: entity.path
```

* `FilePickerCallback.onResult` 签名不变，返回的仍是**原图实体**（顺序/数量语义不变）；
* 想拿非破坏的编辑参数（比如自己再做一次编辑、或做服务端处理）时，新增可选回调
  `onResultWithEdit(entities, sessions)`，默认不实现则完全兼容旧行为；
* "原图"开关语义：
  * 未编辑 → 按原逻辑（原文件 / 压缩件）；
  * 已编辑 → 发送的是**编辑后的文件**（必然重编码过），"原图"只影响未编辑项。

### 2.4 临时文件生命周期

| 时机 | 动作 |
|---|---|
| 编辑确认 | 写 `previewFile`，后台写 `editedFile` |
| 取消编辑 | 删该会话两个文件，回原图 |
| 取消选择 / 关闭选择器 | 删该会话文件 |
| 选择器启动时 | 清 `edit/` 下超过 24h 的残留（防崩溃/杀进程遗留） |
| 兜底 | 总大小超过阈值（如 200MB）按最旧优先清理 |

### 2.5 编辑覆盖的生效范围（本次选择内持久）

需求明确：**在本次选择过程中，列表展示的内容就是编辑之后的图；不管怎么取消选择/重新选择，
都不会退回原图；但磁盘上的真实图片不受影响。**

由此确定：

* 覆盖挂在**原图 path** 上（不是选中项上），所以「取消选中 → 重新选中」后仍是编辑后的图；
* 覆盖只在**本次选择器会话**内有效；关闭选择器 / 进程结束即失效（临时文件随后清理）；
* 网格、预览页、底部缩略图条**同一套查找**：`editedPath ?: path`，所以三处永远一致；
* 提供可选「还原原图」动作：清除该 path 的覆盖 + 删临时文件（默认不做进 UI，API 可调）；
* 磁盘原图、相册 MediaStore **零写入**。

### 2.6 已编辑角标（25dp，左下角）

已编辑的图片需要在缩略图**左下角**显示一个小角标，用需求方提供的图标：

| 项 | 规格 |
|---|---|
| 图标资源 | `filepicker_ic_image_edited.png`（已放入 `filepicker/src/main/res/drawable-xxxhdpi/`，100×100px = 25dp@4x） |
| 尺寸 | **25dp**（可配，默认 25dp） |
| 位置 | 缩略图**左下角**，留 2dp 内边距 |
| 显示条件 | `entity.isEdited`（有编辑覆盖） |
| 显示位置 | ①网格格子（主）②底部缩略图条（可配，默认显示，尺寸可缩到 12~16dp）③预览页不显示 |
| 可配置 | `setEditedBadgeIcon(resId)` / `setEditedBadgeSize(dp)` / `setEditedBadgeVisible(Boolean)` |
| 观感 | 图标是白色，深色缩略图上清晰；浅色缩略图建议加 1dp 阴影或半透明黑底（可配） |

> 角标只是显示，不参与排序/选择/计数逻辑。

## 三、架构（分层 + 会话覆盖）

```
EditSession
 ├─ sourceUri / sourceBitmap  原图 + 屏幕级降采样图
 ├─ viewMatrix                图片↔屏幕
 ├─ baseRect                 裁剪结果（原图坐标）
 ├─ layers:
 │   ├─ doodleLayer   Bitmap(屏幕级) + ops: List<DoodleOp>
 │   ├─ mosaicMask    Bitmap(屏幕级，Alpha 蒙版) + ops: List<MosaicOp>
 │   ├─ textItems     List<TextItem>（矢量参数）
 │   └─ stickers      List<StickerItem>（矢量参数）
 ├─ ops: List<EditOp>         全局操作栈（撤销/重做）
 ├─ redoStack
 └─ outputs: previewFile / editedFile
```

**两类图层要分开处理**：

* **位图层**（涂鸦、马赛克蒙版）：编辑时用屏幕级 Bitmap 立即反馈（快），
  导出时按原图分辨率**用矢量 op 重画**（清晰）；
* **参数层**（文字、贴纸）：只存参数（内容/坐标/字号比例/角度），任意分辨率都能重画。

## 四、各工具算法（按真实交互修正）

### 4.1 裁剪（自由框 + 8 把手 + 旋转 + 镜像 + 还原）

**交互定稿（真机验证）**：

* **固定比例模式（头像 1:1）**：框大小**固定**（屏幕短边 86% 居中，横图竖图都一样大），
  图片按"覆盖框"缩放（`minScale = max(框宽/图宽, 框高/图高)`），最大放大 4 倍；
* **底部按钮**：`取消` ｜ `旋转`（图标）｜ `镜像`（图标）｜ `还原` ｜ 右侧绿色 `确定`
  （`#04AD0C`，和首页确定按钮同款）；
* **手势**：单指拖动图片、双指缩放（以手指焦点为中心）+ 双指拖动；
  **多指抬起时重置基准点**，松手不会跳（此前的"窜"就是没重置基准导致）；
* **导出**：`bakeMatrix` 记录用户旋转/镜像的累计变换，导出时作用在解码后的原图上再裁剪，
  和屏幕看到的完全一致。

* 框在屏幕坐标系，用 `RectF` + 8 个把手命中区域（每个把手 ~24dp 热区）；
* 拖角：对角固定、比例自由，最小尺寸钳制（如 48dp）；
* 拖边：只改一条边，仍受最小尺寸 + 图片边界钳制；
* 移动：拖框内部平移整框；
* 约束：框必须完全落在**图片显示区域**内（不是屏幕）；
* 旋转：每次 90°，旋转图片矩阵 + 交换框宽高 + 重新钳制；
* 还原：框重置为图片当前显示区域（`还原` 置灰判断 = 框 == 初始框 && 未旋转）；
* 导出：`框 → 逆矩阵 → 原图像素 rect` → `BitmapRegionDecoder` 只解这块；
* **比例预设不需要**（微信没有）；但 API 仍保留 `aspectRatio` 能力，给头像 1:1 复用。

### 4.2 涂鸦（8 色 + 橡皮）

* 8 种颜色 + 橡皮（橡皮 = 在涂鸦层 `PorterDuff.CLEAR` 或用背景色擦）；
* 一笔 = 一个 op；点采样 → 二次贝塞尔平滑（`quadTo(中点)`）；
* 屏幕级图层即时绘制，导出时按原图分辨率重画路径（矢量，放大不糊）。

### 4.3 文字（白字 + 描边/阴影）

* op 存：内容、原图坐标、字号（相对原图宽比例）、颜色、描边/阴影、角度；
* 白色文字 + 深色描边是微信观感；`StaticLayout` 多行 + `Paint.setStyle(STROKE)` 画描边；
* 拖动移动、双指缩放旋转；点文字进入编辑（改内容/颜色）。

### 4.4 表情/贴纸（不做）

需求方确认没有表情包资源，从范围中删除。

### 4.5 马赛克（两种笔刷 + 橡皮）

| 笔刷 | 算法 |
|---|---|
| **像素马赛克 ▦** | 图片缩到 `1/B`（B≈16~24px）→ **最近邻**放大回原尺寸 → 用涂抹路径 `clipPath` 只画在笔迹区 |
| **模糊 ◉** | 预计算一张"模糊图"（降采样 1/8 + 三次 box blur 或 StackBlur + 双线性放大回原尺寸）→ 同样用笔迹路径裁剪后叠加 |
| **橡皮 ◇** | 在 `mosaicMask` 上用 `PorterDuff.CLEAR` 擦除蒙版，马赛克消失 |

* 笔刷直径 = 块大小 × 2~3；
* 只存**矢量蒙版路径**（原图坐标），导出时按原图分辨率重算块大小/模糊半径；
* 蒙版层是 Alpha 位图，比每个 op 存位图省内存。

### 4.6 撤销 / 重做（全局）

* 单一操作栈：`ops` + 指针；撤销=指针左移重绘，重做=右移；产生新操作清空 redo；
* **绝不使用位图快照栈**（一张屏幕图 ~8MB，10 步就 OOM）；
* 图层内容由 op 重放得到：`重绘 = 清空图层 → 依次应用 ops`（可做增量优化）。

### 4.7 导出（完成，两阶段）

* 按原图尺寸（或 `setAvatarCropOutputMaxSize` 上限）建结果 Bitmap；
* 顺序：裁 base → 涂鸦层（原图分辨率重画路径）→ 马赛克（重算块/模糊）→ 文字 → 贴纸；
* JPEG q90（透明场景 PNG），EXIF 方向归一化；
* 大图分块渲染，避免 >100MB 瞬时内存；
* **两阶段产出**：编辑确认先出屏幕级 `previewFile`（界面立即生效），
  原图级 `editedFile` 后台产出；删除/取消时连同临时文件一起清理，**不触碰相册原图**。

## 五、内存与性能

| 问题 | 做法 |
|---|---|
| 原图 4000×3000（~48MB） | 编辑期用屏幕级降采样；导出按原图重放矢量 op |
| 每帧重绘 | 只重绘脏区；手势期间只改 Matrix，图层内容不重绘 |
| 模糊预计算 | 打开编辑器时后台生成一次模糊图（缩略级），复用 |
| 导出慢 | 分块 + 后台线程 + 进度回调，导出时禁止工具操作 |
